# MESH-X Message Format & Local Database Schemas

## 1. Message Payload Semantics

Within the MESH-X ecosystem, text payloads transmitted inside LoRa frames are encoded as UTF-8 byte streams.

### 1.1 Direct Message Payload Format
```
+---------------+----------------+--------------------------------------+
| TIMESTAMP(32) | CONV_ID (32b)  | TEXT MESSAGE STRING (UTF-8, 1-227 B) |
+---------------+----------------+--------------------------------------+
```
- `TIMESTAMP`: 32-bit Unix epoch timestamp (seconds) generated by sender.
- `CONV_ID`: 32-bit conversation / thread hash.
- `TEXT MESSAGE`: UTF-8 text string (up to ~180-220 characters to fit a single LoRa frame).

## 2. Message Delivery States

| State | Definition | Visual Indicator |
|---|---|---|
| **`DRAFT`** | Message composed in UI, not yet submitted. | Local composer |
| **`QUEUED`** | Stored in SQLite database; waiting in memory queue for BLE transfer or radio transmit slot. | Single hollow clock icon |
| **`TRANSMITTED`** | ESP32 has confirmed complete physical LoRa packet transmission over the air. *Does not imply recipient receipt.* | Single checkmark |
| **`DELIVERED`** | Direct end-to-end ACK frame matching `PACKET_ID` was received from the target node. | Double checkmark |
| **`FAILED`** | Radio transmission failed, BLE link dropped before commit, or ACK timeout reached after maximum retries. | Red warning circle + Retry button |

## 3. SQLite Database Schema (Mobile Client)

The local Flutter client maintains an embedded SQLite database using `sqflite`.

### 3.1 Table: `conversations`
```sql
CREATE TABLE conversations (
    id TEXT PRIMARY KEY,               -- Hex string of remote Node ID or 'broadcast'
    title TEXT NOT NULL,               -- Nickname or 'All Broadcast'
    peer_node_id INTEGER NOT NULL,     -- 32-bit Node ID (0xFFFFFFFF for broadcast)
    last_message_text TEXT,
    last_message_timestamp INTEGER,
    unread_count INTEGER DEFAULT 0,
    is_pinned INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

### 3.2 Table: `messages`
```sql
CREATE TABLE messages (
    id TEXT PRIMARY KEY,               -- UUID v4 string (client-side stable ID)
    packet_id INTEGER NOT NULL,        -- 32-bit over-the-air packet identifier
    conversation_id TEXT NOT NULL,
    sender_node_id INTEGER NOT NULL,
    recipient_node_id INTEGER NOT NULL,
    text_content TEXT NOT NULL,
    delivery_status TEXT NOT NULL,     -- 'QUEUED', 'TRANSMITTED', 'DELIVERED', 'FAILED'
    is_incoming INTEGER NOT NULL,      -- 0 = outgoing, 1 = incoming
    retry_count INTEGER DEFAULT 0,
    rssi INTEGER,                      -- Received Signal Strength (for incoming)
    snr REAL,                          -- Signal-to-Noise Ratio (for incoming)
    hop_count INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL,
    delivered_at INTEGER,
    FOREIGN KEY(conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);

CREATE INDEX idx_messages_conv ON messages(conversation_id);
CREATE INDEX idx_messages_packet_id ON messages(packet_id);
```

### 3.3 Table: `known_nodes`
```sql
CREATE TABLE known_nodes (
    node_id INTEGER PRIMARY KEY,       -- 32-bit hardware Node ID
    nickname TEXT,
    public_key TEXT,                   -- Base64 Curve25519 public key (Phase 6)
    last_seen_timestamp INTEGER,
    last_rssi INTEGER,
    last_snr REAL,
    hop_distance INTEGER DEFAULT 1,
    is_favorite INTEGER DEFAULT 0
);
```

### 3.4 Table: `settings`
```sql
CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

## 4. Message Deduplication Guarantee
- Inbound messages received via BLE `EVT_RX_MESSAGE` are inspected before insertion.
- SQLite query checks `SELECT id FROM messages WHERE packet_id = ? AND sender_node_id = ?`.
- If an entry exists within the past 10 minutes, the duplicate is ignored and not rendered again in the UI.
